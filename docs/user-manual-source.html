BAB 1: Pengenalan & Gambaran Umum Sistem

Fondasi & Akses

1.1 Latar Belakang & Tujuan TrackIT

TrackIT adalah sistem enterprise internal yang dirancang dan dikembangkan secara khusus untuk mendukung operasional TrackIT Project. Platform ini menghubungkan manajemen inventaris perangkat kerja (IT, General Affairs, dan Operasional Store/Resto), penanganan tiket bantuan helpdesk dengan SLA ketat, pelacakan pengiriman logistik antarcabang, formulir Berita Acara Serah Terima (BAST), serta pusat edukasi dan panduan troubleshooting mandiri (Help Center).

Tujuan utama dari implementasi TrackIT meliputi:

  • Sentralisasi Data Aset: Menghilangkan pencatatan aset yang tercecer di berbagai spreadsheet manual dengan database PostgreSQL terpusat.
  • Akuntabilitas & Audit Mutasi: Mencatat riwayat perpindahan laptop, PC, dan perangkat toko dari satu karyawan ke karyawan lainnya secara transparan.
  • Peningkatan Responsivitas Helpdesk: Memastikan insiden teknis di kantor pusat maupun outlet resto tertangani tepat waktu sesuai target SLA dengan notifikasi live.
  • Pemberdayaan Karyawan (Self-Service): Menyediakan portal Help Center berisi artikel panduan (*playbook*) dan template pesan siap pakai untuk memecahkan kendala umum tanpa harus menunggu tim teknisi.

1.2 Arsitektur Sistem & Teknologi

Sistem ini dibangun dengan arsitektur modern berstandar tinggi yang mengutamakan kecepatan, reaktivitas waktu nyata, dan integritas data:

Komponen Teknologi Terpasang Peran & Keunggulan
Frontend SPA Vue 3 (Composition API), Vite, Tailwind CSS 4 Antarmuka responsif super cepat, state management reaktif, dan transisi halaman halus (*GSAP animations*).
Backend API Node.js ESM, Express 5, `pg` driver RESTful API modular dengan validasi skema runtime, pooling koneksi database aman, dan performa I/O tinggi.
Real-Time Engine Server-Sent Events (SSE) Pengiriman event tiket baru, pembaruan status, dan komentar obrolan secara live ke browser tanpa perlu refresh.
Database Utama PostgreSQL 15+ Database relasional tangguh dengan ledger migrasi versioned (*canonical SQL*), audit logging, dan index teroptimasi.
Keamanan Data JWT (HttpOnly Cookie), CORS Whitelist, CSRF, Rate Limiting Perlindungan terhadap *brute force*, kebocoran sesi, serta serangan injeksi formula spreadsheet pada file Excel.

1.3 Matriks Peran Pengguna (RBAC)

Akses pengguna ke fitur-fitur di dalam aplikasi dikendalikan oleh sistem Role-Based Access Control (RBAC) yang terbagi menjadi 3 tingkatan utama:

Superadmin Akses Penuh Sistem

Peran tertinggi yang memegang wewenang penuh atas seluruh aplikasi.

  • Mengelola semua aset (IT, GA, OPS) dan karyawan.
  • Mengatur akun pengguna, penugasan peran, dan hak akses modular.
  • Melakukan backup, restore skema, migrasi, dan reset database.
  • Melakukan ekspor administratif lintas tabel tanpa batasan.
Admin Pengelola Operasional

Peran untuk tim IT Support, Helpdesk Leader, GA, dan Asset Management.

  • Menginput, mengedit, mencetak label, dan mengaudit aset IT/GA/OPS.
  • Menangani antrean tiket, mengubah status, dan menulis catatan internal.
  • Membuat formulir BAST serah terima dan memperbarui resi pengiriman.
  • Mengelola artikel di CMS Help Center dan daftar FAQ.
Reporter / User (Karyawan) Akses Layanan Mandiri

Peran default untuk seluruh staf dan karyawan perusahaan. Memiliki akses langsung ke:

  • Help Center Publik: Membaca seluruh artikel troubleshooting, panduan SOP, dan menyalin template pesan.
  • Aset Saya (My Assets): Melihat daftar perangkat inventaris perusahaan yang sedang dipinjamkan ke NIK karyawan yang bersangkutan.
  • Tiket Helpdesk: Membuat tiket pelaporan kendala baru, berinteraksi di kolom komentar tiket publik, dan memberikan nilai kepuasan (CASP) setelah penanganan selesai.

1.4 Izin Granular & Navigasi Antarmuka

Selain peran global, sistem menyediakan pengaturan izin granular per fitur dengan 3 tingkatan: None (Tidak Dapat Mengakses), Read Only (Hanya Melihat), dan Full (Melihat, Menambah, Mengubah, & Menghapus Data).

Modul / Fitur Superadmin Admin User / Reporter Keterangan Izin
Help Center & Cases Full Full Read Only User membaca artikel; Admin/Superadmin mengelola di CMS.
Dashboard Monitoring Full Read Only None Hanya untuk staf operasional dan pengambil kebijakan.
Aset IT, GA, & OPS Full Full / Read None Dibatasi pada tim pengelola inventaris.
Aset Karyawan (My Assets) Full Full Read Only User melihat aset yang terikat pada NIK miliknya.
Tiket Helpdesk Full Full Full (Self) User mengelola tiket miliknya; Admin menangani seluruh tiket.
BAST & Pengiriman Full Full / Read None Pencatatan serah terima fisik dan ekspedisi logistik.
Master Karyawan & Users Full Read / Full None Hanya untuk administrator dan tim HR/Asset.
Database & Ekspor Penuh Full None None Khusus Superadmin untuk menjaga integritas data kritikal.
ℹ
Navigasi Dual Mode (Desktop Sidebar & Collapsed Rail): Pada layar desktop, pengguna dapat memperluas menu navigasi (245px) atau menciutkannya menjadi *Navigation Rail* (74px) dengan tombol panah di samping logo. Saat mode rail aktif, hover mouse di atas ikon menu akan memunculkan menu melayang (*floating flyout popover*) tanpa menghabiskan area pandang kerja Anda.

BAB 2: Pusat Bantuan & Knowledge Base (Help Center)

Layanan Mandiri & Edukasi

2.1 Halaman Depan & Pencarian Pintar

Halaman Pusat Bantuan (dapat diakses pada rute /) merupakan gerbang utama yang langsung terbuka bagi seluruh pengguna tanpa keharusan login terlebih dahulu. Halaman ini dirancang bersih, intuitif, dan bebas hambatan visual untuk memberikan jawaban instan atas permasalahan kerja sehari-hari.

  • Kolom Pencarian Utama: Dilengkapi fitur pencarian pintar instan (*fuzzy search*) dengan *live suggestions*. Saat pengguna mengetik kata kunci (misal: "password" atau "printer"), sistem secara dinamis menampilkan judul artikel relevan dan ringkasan ringkasnya di bawah kolom input.
  • Pencarian Populer (Trending Searches): Menyajikan tagar kata kunci yang paling sering ditelusuri pengguna (seperti Password Reset, VPN Setup, Hardware Request). Klik pada tagar untuk langsung memfilter artikel.
  • Kartu Topik Kategori: Navigasi berdasarkan klasifikasi sistem (Hardware, Software, Jaringan & WiFi, Akses & Keamanan, Sistem POS Toko, dan General Affairs).
  • SOP Unggulan (Featured SOPs): Pintasan langsung ke SOP standar penting seperti SOP Setup Laptop Baru New Joiner dan SOP Setup Laptop Re-use.

Komponen akordeon FAQ interaktif di halaman utama menyajikan jawaban cepat atas pertanyaan yang paling sering diajukan karyawan terkait operasional harian, kebijakan penggantian laptop kerja, prosedur peminjaman perangkat tes, hingga perpanjangan akun email.

2.5 Help Center Analytics & Admin CMS

Bagi tim administrator dan dokumentasi, modul CMS (/admin/cases dan /admin/editor) memungkinkan pembuatan dan pengeditan artikel panduan menggunakan rich text editor:

  • Manajemen Status Artikel: Opsi penyimpanan artikel sebagai Draft (hanya terlihat oleh tim admin) atau Published (dapat dibaca oleh seluruh karyawan).
  • Atur Kategori & Kartu Topik: Mengelola ikon, label, dan urutan kartu kategori di /admin/kb-categories.
  • Analisis Celah Informasi (Gap Analysis): Dashboard analitik (/kb-analytics) merekam metrik istilah pencarian yang dimasukkan pengguna. Jika ada query pencarian yang sering dicari namun tidak menghasilkan artikel, admin dapat segera menulis panduan baru untuk menutup celah tersebut.

BAB 3: Modul Manajemen Aset (Asset Management)

Inventaris & Audit Fisik

Halaman Aset IT (/assets) adalah pusat kendali untuk seluruh perangkat komputasi perusahaan. Sistem menyimpan informasi aset secara mendalam dengan atribut-atribut utama berikut:

Atribut Data Penjelasan & Format Contoh Nilai

Tipe Perangkat Kategori jenis unit hardware kerja. Laptop, Desktop, Server, Monitor, Printer, Network Device

Kondisi Fisik Tingkat kelayakan fungsi dan fisik unit. Baru, Normal, Rusak Ringan, Rusak Sedang, Rusak Berat

3.2 Riwayat Pemakaian & Audit Log Aset (Device Logs)

Setiap kali terjadi mutasi perangkat (misalnya laptop diserahkan dari Karyawan A ke Karyawan B, atau unit dipindahkan dari status *In Use* menjadi *In Service* di vendor perbaikan), sistem secara otomatis mencatat riwayat tersebut ke dalam tab Device Logs di dalam modal Detail Aset.

Hal ini menjamin transparansi riwayat audit sehingga tim Asset Management dapat melacak rekam jejak pengguna masa lalu, tanggal serah terima, dan riwayat perbaikan fisik tanpa khawatir ada data yang hilang.

3.3 Generator & Cetak Label Aset (QR Code / Barcode)

Untuk memudahkan proses audit inventaris fisik di lapangan, setiap baris data aset dilengkapi tombol Label Aset:

  • Sistem merender kartu label beresolusi tinggi berisi informasi: Logo aplikasi, Hostname, Serial Number, Tipe Perangkat, Tanggal Perolehan, dan QR Code terenkripsi.
  • QR Code tersebut dapat dipindai (*scan*) menggunakan kamera smartphone atau barcode scanner untuk langsung membuka halaman verifikasi detail aset.
  • Tersedia tombol Cetak Label yang telah diformat pas dengan ukuran kertas stiker label fisik standar industri.

3.4 Aset General Affairs (GA) & Aset Operasional Resto (OPS)

Selain perangkat teknologi informasi, TrackIT menyediakan dua modul inventaris terpisah dengan basis database yang diisolasi:

Aset GA (General Affairs)

Pengelolaan inventaris sarana dan fasilitas kantor non-IT:

  • Perabot kantor (meja ergonomis, kursi kerja, lemari brankas arsip).
  • Fasilitas gedung (unit AC, genset cadangan, pemadam api ringan/APAR).
  • Perangkat keamanan (CCTV gedung, sistem kunci akses sidik jari).
Aset OPS (Operasional Resto / Store)

Inventaris khusus perlengkapan gerai dan dapur resto:

  • Mesin kasir POS khusus gerai, laci uang otomatis (*cash drawer*).
  • Kitchen Display System (KDS), thermal printer pesanan dapur.
  • Peralatan dapur operasional (chiller, microwave komersial, scale digital).

3.5 Portal Aset Saya (My Assets) untuk Karyawan

Halaman Aset Karyawan (/my-assets) dirancang khusus sebagai antarmuka *self-service*. Ketika seorang karyawan masuk (*login*), sistem secara otomatis mencocokkan NIK pengguna dengan database aset:

  • Karyawan dapat melihat seluruh unit yang resmi terdaftar atas namanya (misal: Laptop Lenovo ThinkPad dan Monitor Eksternal 24 inci).
  • Menampilkan rincian tanggal serah terima, kondisi saat diterima, nomor seri unit, dan catatan spesifik.
  • Jika terdapat ketidaksesuaian data fisik dengan sistem, karyawan dapat langsung menekan tombol Laporkan Ketidaksesuaian yang akan otomatis membuka tiket helpdesk ke tim Asset Management.

3.6 Prosedur Import & Export Excel (XLSX)

Fitur Import/Export Excel di TrackIT telah diselaraskan agar format file hasil Export memiliki header dan kolom sheet yang 100% sama dengan template Import. Dengan demikian, file ekspor dapat diedit langsung lalu diimpor kembali ke sistem.

Modul Target Nama Sheet Utama Identitas Kunci Aturan & Keterkaitan Data
Karyawan Table Karyawan NIK Karyawan Template hanya memuat profil karyawan. NIK wajib unik.
Aset IT Standar Table Asset Hostname Import Karyawan terlebih dahulu agar kolom NIK Pemegang terhubung otomatis.
Aset IT Lengkap Table Karyawan + Table Asset NIK & Hostname Pilihan import awal dua sheet sekaligus untuk instalasi data baru.
Aset GA Data Aset GA Nomor Inventaris Sheet mandiri terpisah khusus fasilitas non-IT.
Aset OPS Data Aset OPS Nomor Seri / Hostname Sheet mandiri khusus inventaris resto.
Pengiriman Data Pengiriman Nomor Resi Header impor dan ekspor identik untuk memudahkan pelacakan logistik.
⚠
Aturan Penggantian Data (Replace All vs Tambah Data):
• Tambah Data: Menambahkan data baru dari file Excel tanpa menghapus rekaman data yang sudah ada di database.
• Replace All: Menghapus seluruh data lama pada tabel target, lalu memasukkan isi file Excel yang baru. Untuk keamanan, sistem mewajibkan admin mengetik kata sandi konfirmasi GANTI secara persis sebelum proses dijalankan. Validasi ini juga diverifikasi ganda oleh server (*server-side security guard*).
🛡
Proteksi Formula Injection: Untuk melindungi workstation dari serangan spreadsheet injection, setiap sel data hasil ekspor yang diawali karakter formula berbahaya seperti =, +, -, atau @ akan dinetralkan secara otomatis oleh mesin sanitasi backend sebelum ditulis ke workbook Excel.

BAB 4: Modul Helpdesk & Tiket Kendala

Dukungan & Layanan IT

4.1 Alur Pelaporan Kendala & Antrean Tiket (Queues)

Modul Tiket (/tickets) adalah sarana formal bagi seluruh karyawan dan operasional cabang untuk mengajukan permohonan bantuan teknis, perbaikan kerusakan, peminjaman perangkat, maupun permohonan hak akses software.

Saat membuat tiket baru melalui tombol + Tiket Baru, pengguna mengisi informasi:

  • Judul Tiket: Ringkasan singkat permasalahan (contoh: Printer Thermal POS Kasir Outlet Sudirman Tidak Merespon).
  • Antrean Divisi (Ticket Queue): Pemilihan divisi penanggung jawab, seperti IT Support, Hardware Maintenance, Network & WiFi Infrastructure, atau POS System Support.
  • Tingkat Kepentingan (Prioritas): Pilihan estimasi dampak urgensi (Low, Medium, High, Critical).
  • Deskripsi Detail: Penjelasan rinci kendala, langkah-langkah yang sudah dicoba, dan waktu terjadinya masalah.
  • Lampiran Foto / File: Bukti visual screenshot pesan error atau foto fisik perangkat.

4.2 Siklus Hidup Status Tiket & Countdown SLA

Tiket yang diajukan akan bergerak melalui siklus hidup terstandarisasi untuk memastikan kepatuhan Service Level Agreement (SLA):

Open
Tiket Diterima
Tiket baru berhasil dibuat oleh pelapor. Menunggu penugasan teknisi (*assignment*). Timer SLA mulai berjalan mundur.
In Progress
Sedang Dikerjakan
Teknisi IT telah mengambil tiket dan aktif melakukan investigasi, pengujian, atau perbaikan perangkat.
Pending
Menunggu Tindak Lanjut
Pekerjaan tertahan sementara karena menunggu suku cadang vendor, respon konfirmasi user, atau persetujuan atasan.
Resolved
Solusi Diterapkan
Kendala telah diselesaikan oleh teknisi. Pelapor menerima notifikasi dan diminta memvalidasi hasil perbaikan.

Setelah status Resolved divalidasi dan pelapor memberikan penilaian kepuasan, tiket akan otomatis berubah menjadi Closed (Selesai Sepenuhnya) dan diarsipkan dalam riwayat sistem.

Tingkat Prioritas Warna Indikator Target Respons Pertama Target Batas Waktu Resolusi (SLA)
Critical Merah Berkedip ≤ 15 Menit ≤ 2 Jam (Downtime sistem kasir toko, server down)
High Kuning Amber ≤ 30 Menit ≤ 4 Jam (Karyawan tidak bisa bekerja, printer kasir mati)
Medium Biru Langit ≤ 2 Jam ≤ 8 Jam Kerja (Kendala software minor, email lambat)
Low Hijau Emerald ≤ 4 Jam ≤ 24 Jam Kerja (Permintaan informasi, setup akun baru)

4.3 Komunikasi Real-Time (SSE) & Catatan Internal

Halaman tiket dilengkapi dengan mesin Server-Sent Events (SSE) terintegrasi:

  • Setiap kali ada tiket baru dibuat oleh user atau status tiket diperbarui oleh teknisi, seluruh layar admin yang sedang aktif akan langsung terupdate dalam hitungan milidetik tanpa perlu memuat ulang (*refresh*) browser. Notifikasi lonceng banner juga akan muncul di pojok kanan atas.
  • Kolom Komentar Ganda (Publik vs Internal):
    • Balasan Publik (Public Reply): Pesan yang dapat dibaca oleh karyawan pelapor untuk memberikan instruksi troubleshooting atau kabar perkembangan perbaikan.
    • Catatan Internal (Internal Note - Berlatar Kuning): Pesan rahasia yang hanya dapat dilihat oleh sesama teknisi IT dan Superadmin, digunakan untuk mencatat koordinasi teknis, password sementara perbaikan, atau catatan vendor.

4.4 Penilaian Kepuasan Pengguna / CASP (Customer Satisfaction)

Ketika teknisi menandai tiket menjadi status Resolved, kartu evaluasi CASP Rating akan muncul di layar pelapor:

  • Pelapor memberikan skor bintang kepuasan (skala 1 sampai 5) atas keramahan dan kecepatan teknisi.
  • Pelapor dapat menyertakan komentar ulasan kepuasan layanan.
  • Data CASP ini langsung direkam ke metrik kepuasan helpdesk bulanan untuk evaluasi kinerja divisi IT.

BAB 5: Modul Transaksi & Logistik

BAST & Ekspedisi

5.1 Formulir BAST (Berita Acara Serah Terima) Aset

Halaman BAST / Submissions (/submissions) berfungsi untuk mengotomatisasi pembuatan dokumen formal serah terima aset perusahaan, menggantikan proses pengetikan surat manual di dokumen pengolah kata.

Struktur pengisian formulir BAST mencakup:

  • Pihak Pertama (Pemberi): Memilih NIK karyawan penyerah aset (biasanya staf Asset Management atau IT Support). Nama lengkap dan direktorat terisi secara otomatis dari database karyawan.
  • Pihak Kedua (Penerima): Memilih NIK karyawan penerima fasilitas kerja (misal: karyawan baru atau karyawan yang menerima unit pengganti).
  • Pihak Ketiga (Mengetahui): Secara default diisi oleh perwakilan People Business Partner (PBP) atau pimpinan unit kerja untuk memvalidasi legalitas serah terima.
  • Tujuan Penyerahan: Pilihan kategori transaksi: Penyerahan Aset Baru, Peminjaman Sementara, Perbaikan / Service, atau Disposal / Pengembalian Unit.
  • Daftar Aset Baru (Diserahkan): Memilih unit perangkat dari master aset lengkap dengan jumlah (*qty*) dan spesifikasinya.
  • Daftar Aset Lama (Ditarik): Memilih unit laptop lama milik karyawan yang ditarik kembali ke gudang IT.
🖨
Pencetakan Dokumen BAST Resmi: Setelah formulir disimpan, pengguna cukup menekan tombol Cetak Dokumen BAST. Sistem akan merender surat resmi Berita Acara lengkap dengan nomor referensi unik, rincian tabel perangkat, klausul perjanjian pemeliharaan aset perusahaan, serta tiga kolom tanda tangan basah/digital pihak terkait.

5.2 Pelacak Pengiriman Aset (Shipments Logistics Tracker)

Halaman Pengiriman (/shipments) memantau pergerakan fisik perangkat yang dikirimkan melalui jasa ekspedisi kurir antarkantor cabang, pengiriman ke rumah karyawan remote (*work from home*), maupun pengiriman unit rusak ke pusat servis vendor rekanan.

Kolom Data Deskripsi Fungsi Operasional
Tanggal Request Tanggal permintaan pengiriman dibuat Pencatatan SLA proses persiapan unit di logistik.
Penerima & Tujuan Nama orang dan alamat tujuan lengkap Memastikan kurir mengantar ke lokasi cabang/alamat yang tepat.
Rincian Barang Deskripsi fisik unit yang dipaketkan Contoh: 1 Unit Laptop ThinkPad T14 + Charger + Mouse.
Nomor Resi (AWB) Kode pelacakan resi ekspedisi Nomor AWB dari JNE, J&T, SiCepat, atau kurir internal perusahaan.
Status Pengiriman Status tracking real-time Belum Dikirim → Pending → Sedang Dikirim → Diterima (atau Cancel)
Bukti Terima (POD) Tautan foto Proof of Delivery Foto resi bertanda tangan atau foto penerima saat paket sampai.

Modul pengiriman juga dilengkapi dengan modal Import Pengiriman dan Export Pengiriman untuk memperbarui status ratusan resi ekspedisi sekaligus dari laporan harian vendor kurir.

BAB 6: Administrasi Master Data

Karyawan & Akun Pengguna

6.1 Master Data Karyawan (Employees)

Halaman Karyawan (/karyawan) bertindak sebagai sumber kebenaran tunggal (*single source of truth*) data identitas staf di TrackIT. Data ini menjadi pondasi bagi modul Aset (menentukan pemegang perangkat) dan modul Tiket (menentukan pihak pelapor).

  • NIK (Nomor Induk Karyawan): Kunci primer unik identitas karyawan (misal: TK-2024-105).
  • Nama Lengkap & Email: Kontak resmi korespondensi notifikasi tiket.
  • Departemen & Jabatan: Pengelompokan divisi kerja (misal: Engineering, Product, Marketing, People & Culture, Finance).
  • Level Jabatan (Job Level): Pilihan terstandarisasi: C-Level, L1 s/d L6, LS1 s/d LS3, Freelance, dan Intern.
  • Lokasi Kerja: Penempatan fisik kantor pusat, regional hub, atau remote store.
  • Hierarki Atasan Langsung: Menghubungkan NIK atasan (Manager/Supervisor) untuk alur eskalasi persetujuan pengadaan perangkat baru.
🔄
Sinkronisasi Akun Otomatis: Saat administrator mengimpor data karyawan melalui file Excel, sistem secara cerdas memeriksa apakah karyawan tersebut sudah memiliki akun login di tabel users. Jika belum, akun login baru dengan username berbasis NIK dan kata sandi default sistem akan dibuatkan secara otomatis.

6.2 Manajemen Pengguna Sistem (Users & Access Control)

Halaman Pengguna (/users) digunakan oleh administrator untuk mengontrol hak masuk (*authentication*) dan hak eksekusi (*authorization*) ke dalam platform TrackIT:

Tindakan Pengelolaan Hak Akses Pelaksana Fungsi & Dampak Terhadap Sistem
Tambah Pengguna Baru Superadmin, Admin Membuat akun dengan mengaitkan NIK karyawan, email login, username, dan password awal.
Penetapan Peran (Role) Superadmin Menetapkan hak sebagai Superadmin, Admin, atau Reporter.
Konfigurasi Izin Modular Superadmin Menentukan apakah pengguna memiliki hak Full Access, Read Only, atau No Access pada tiap modul (Dashboard, Aset, Tiket, BAST, Ekspor, dll).
Penugasan Antrean (Queues) Superadmin, Admin Menentukan antrean tiket mana saja (IT Support, Hardware, Network, POS) yang dapat ditangani oleh teknisi yang bersangkutan.
Reset Kata Sandi Superadmin, Admin Mereset kata sandi akun pengguna jika staf yang bersangkutan lupa kata sandi.
Aktivasi / Suspend Akun Superadmin Menonaktifkan akses login staf yang telah mengundurkan diri (*resigned*) demi keamanan data.

BAB 7: Sistem, Pemeliharaan & Audit Keamanan

Audit Trail & Keamanan Database

7.1 Log Aktivitas Sistem (Audit Trail)

Halaman Log Aktivitas (/logs) merekam setiap jejak digital tindakan operasional penting yang terjadi di dalam platform secara kronologis dan tidak dapat dimanipulasi (*tamper-proof*).

Informasi yang direkam mencakup:

  • Aktor (Pengguna): Nama, username, dan alamat IP perangkat yang mengeksekusi tindakan.
  • Tipe Tindakan: Aktivitas Login, Logout Gagal, Penambahan Data Baru (*Create*), Pengubahan Atribut (*Update*), Penghapusan Rekaman (*Delete*), Eksekusi Import/Export, serta Pemulihan Database.
  • Modul Terkait: Bagian sistem yang mengalami perubahan (misal: ASSETS, TICKETS, USERS).
  • Rincian Perubahan (Payload): Nilai data sebelum diubah (*before*) dan nilai data setelah diubah (*after*).
  • Timestamp Presisi: Tanggal dan waktu detik terjadinya peristiwa.

7.2 Pusat Ekspor Data Lanjutan (Advanced Export Hub)

Halaman Ekspor Data (/export) khusus disediakan bagi Superadmin untuk kebutuhan pembuatan laporan manajerial, audit eksternal, dan arsip data historis:

  • Ekspor Cepat (Quick Export): Mengunduh seluruh isi tabel utama (Aset TI, Aset GA, Aset OPS, Karyawan, Tiket, Pengiriman) dalam 1 klik ke format Excel (XLSX).
  • Ekspor Kustom (Custom Export): Superadmin dapat memilih tabel tertentu, mencentang kolom mana saja yang ingin disertakan, menentukan filter rentang tanggal (*Date From - Date To*), membatasi jumlah baris (50, 100, 500, 1000, atau Semua Baris), serta memilih format keluaran antara Excel (.xlsx), CSV, JSON, atau PDF Laporan Resmi.

7.3 Pusat Database & Pemulihan Bencana (Disaster Recovery)

Halaman Database (/database) memberikan wewenang penuh kepada Superadmin untuk memantau integritas dan kesehatan penyimpanan PostgreSQL:

Fitur Database Fungsi Utama Mekanisme Keamanan
Status & Health Check Memeriksa ketersediaan koneksi pool, validitas tabel, view skema, dan utilitas `pg_dump`/`pg_restore`. Peringatan otomatis bila terdapat skema yang hilang (*missing schema*).
Snapshot Backup Membuat salinan cadangan kompresi database lengkap (skema DDL dan baris data DML). Backup disimpan di folder terisolasi dengan penamaan timestamp unik.
Restore Wizard Memulihkan database dari file cadangan jika terjadi kegagalan sistem. Validasi berkas sebelum eksekusi; membutuhkan konfirmasi teks ganda.
Database Reset Mengosongkan seluruh data operasional untuk persiapan tahun buku baru atau staging test. Wajib mengetik kata kunci RESET. Server akan menolak jika string tidak cocok.

7.4 Proteksi Keamanan Berlapis (Multi-Layer Security)

Aplikasi dilindungi oleh beberapa lapis pengamanan infrastruktur:

  • Proteksi Brute Force & Rate Limiter: Membatasi jumlah request per menit dari IP publik dan per akun login terautentikasi untuk mencegah serangan penolakan layanan (DoS) dan pembobolan sandi.
  • Token JWT dengan Sesi Server-Side: Sesi pengguna disimpan dalam cookie HttpOnly yang aman dari pencurian script sisi klien (XSS) dan divalidasi keaktifannya di server.
  • CORS & Origin Whitelist: Permintaan API dari domain tidak dikenal akan langsung ditolak pada layer middleware Express.

BAB 8: Panduan Praktis & SOP Sehari-Hari

Prosedur Operasional Standar

8.1 SOP untuk Pengguna Umum / Karyawan

Langkah Pelaporan Kendala Teknis:
  1. Buka / (Help Center) dan coba cari solusi di kolom pencarian atau baca FAQ.
  2. Jika butuh bantuan teknisi, klik tombol Ajukan Tiket atau masuk ke /tickets.
  3. Isi judul masalah, pilih divisi antrean, tentukan prioritas, dan lampirkan foto kendala.
  4. Pantau perkembangan tiket melalui balasan teknisi di kolom komentar tiket.
  5. Setelah kendala tuntas (*Resolved*), beri nilai bintang kepuasan (CASP) dan ulasan.
Langkah Verifikasi Aset Kerja Pribadi:
  1. Masuk ke menu Aset Karyawan (/my-assets).
  2. Periksa apakah nomor seri dan tipe laptop/monitor yang Anda bawa sesuai dengan tabel.
  3. Cek status serah terima dan tanggal penerimaan perangkat.
  4. Jika ada unit yang belum terdaftar atau unit sudah dikembalikan, klik Laporkan Ketidaksesuaian.

8.2 SOP untuk Teknisi & Admin IT

Penanganan Antrean Tiket Masuk:
  1. Buka menu Tiket (/tickets). Filter berdasarkan antrean tugas Anda.
  2. Buka tiket berstatus Open yang memiliki SLA paling kritis (*Critical* & *High* terlebih dahulu).
  3. Ubah status menjadi In Progress dan berikan respon awal ke pelapor.
  4. Gunakan fitur Catatan Internal untuk mencatat riwayat teknis dengan rekan teknisi.
  5. Setelah perbaikan selesai, ubah status menjadi Resolved.
Pendaftaran & Mutasi Aset IT Baru:
  1. Buka menu Aset IT (/assets) → klik + Tambah Aset.
  2. Masukkan Hostname, Serial Number, Merk/Model, dan Spesifikasi Lengkap.
  3. Pilih NIK Karyawan pemegang unit dan tentukan lokasi kantornya.
  4. Klik tombol Label Aset, cetak stiker QR Code, dan tempelkan pada bodi laptop.
  5. Jika ada perpindahan tangan, buka modal BAST di /submissions untuk cetak bukti serah terima.

8.3 SOP untuk Logistik & General Affairs

  • Pembuatan BAST Serah Terima: Setiap kali ada penyerahan laptop baru atau penarikan perangkat lama karyawan yang keluar (*exit clearance*), wajib mengisi form BAST di /submissions dan mencetak dokumen fisik untuk ditandatangani basah.
  • Pencatatan Pengiriman Ekspedisi: Saat mengirimkan perlengkapan resto atau laptop ke cabang, segera daftarkan paket di /shipments, masukkan nomor resi AWB, dan unggah foto resi ekspedisi. Saat paket telah tiba, ubah status menjadi Diterima dan unggah foto tanda terima (*Proof of Delivery*).

8.4 SOP untuk Superadmin

  • Backup Database Berkala: Lakukan pencadangan database di /database minimal sekali setiap minggu sebelum jam sibuk kantor, atau setiap kali sebelum melakukan migrasi data besar.
  • Audit Log Rutin: Periksa log aktivitas di /logs untuk memantau percobaan login mencurigakan atau penghapusan data aset yang tidak sah.
  • Manajemen Pengguna Baru & Resign: Pastikan karyawan yang mengundurkan diri segera dinonaktifkan status akunnya di menu /users agar hak akses sistem langsung terputus.

8.5 Tanya Jawab & Pemecahan Masalah Umum (FAQ)

❓
Mengapa status tiket saya berubah menjadi "Pending"?
Status Pending berarti teknisi sedang menunggu suku cadang pengganti dari vendor resmi, atau teknisi membutuhkan informasi tambahan dari Anda di kolom komentar tiket. Silakan cek pesan di tiket Anda.
❓
Apa yang harus dilakukan jika gagal mengimpor file Excel ke database?
Pastikan nama sheet di dalam file Excel Anda sesuai persis dengan standar (misal: Table Asset untuk aset IT atau Table Karyawan untuk karyawan). Pastikan tidak ada kolom identitas kunci (NIK atau Hostname) yang kosong atau duplikat.
❓
Bagaimana jika tombol Database / Ekspor tidak muncul di sidebar saya?
Menu Database dan Ekspor tingkat lanjut dirancang khusus hanya untuk peran Superadmin. Jika posisi pekerjaan Anda memerlukan akses tersebut, hubungi Superadmin IT untuk meningkatkan izin akun Anda di menu Pengguna.
